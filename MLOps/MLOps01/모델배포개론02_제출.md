## 체크포인트 답변

### 섹션 1 체크포인트

**Q1. FastAPI가 Flask보다 모델 배포에 적합한 이유 세 가지는 무엇입니까?**

1. **자동 데이터 검증 (Pydantic 내장)**: Pydantic 모델을 선언하는 것만으로 요청 데이터의 타입·범위·필수 여부를 자동 검증하고, 실패 시 상세한 422 에러를 반환한다. Flask는 검증 로직을 직접 작성해야 한다.
2. **자동 API 문서화 (Swagger UI)**: 코드를 작성하는 것만으로 `/docs`에 Swagger UI가 자동 생성되어 별도 문서 작성 없이 브라우저에서 바로 API를 테스트할 수 있다. Flask는 Flask-RESTX 같은 별도 확장이 필요하다.
3. **비동기 처리 (async/await 기본 지원)**: FastAPI는 ASGI 기반으로 비동기 처리를 기본 지원하므로 모델 추론처럼 시간이 걸리는 작업이 있을 때 다른 요청을 블로킹하지 않는다. Flask는 기본적으로 동기(WSGI) 방식이다.

**Q2. Uvicorn의 역할은 무엇이며, 왜 FastAPI와 함께 사용합니까?**

Uvicorn은 **ASGI 서버**로, 외부에서 들어오는 HTTP 요청을 받아 FastAPI 애플리케이션에 전달하는 역할을 한다. FastAPI 자체는 요청을 수신하는 기능이 없는 프레임워크이므로, 실제로 포트를 열고 TCP 연결을 처리하는 Uvicorn이 반드시 필요하다. 비동기 이벤트 루프를 기반으로 동작하여 FastAPI의 `async/await` 기능과 자연스럽게 결합된다.

**Q3. `@app.get("/health")`에서 `get`과 `"/health"`는 각각 무엇을 의미합니까?**

- `get`: HTTP 메서드를 의미한다. 이 엔드포인트는 **GET** 방식 요청만 처리한다.
- `"/health"`: URL 경로(라우트)를 의미한다. `http://서버주소/health`로 들어온 요청이 이 함수로 연결된다.

**Q4. FastAPI에서 dict를 반환하면 어떤 일이 자동으로 일어납니까?**

FastAPI가 Python `dict`를 자동으로 JSON 문자열로 직렬화하여 HTTP 응답의 바디에 담아 반환한다. `Content-Type: application/json` 헤더도 자동으로 설정된다. 즉, `json.dumps()`를 직접 호출하거나 Response 객체를 수동으로 만들 필요가 없다.

### 섹션 2 체크포인트

**Q1. `/models/sentiment-v1`에서 `sentiment-v1`은 어떤 종류의 파라미터입니까?**

**Path 파라미터**이다. URL 경로 자체의 일부로 전달되며, 엔드포인트 정의에서 `{model_name}` 형태의 중괄호로 선언된다. 특정 리소스를 식별할 때 사용한다.

**Q2. `/models?status=running&limit=5`에서 `status`와 `limit`은 어떤 종류의 파라미터입니까?**

**Query 파라미터**이다. URL 뒤에 `?key=value` 형태로 붙어 전달된다. URL 경로에 포함된 `{}` 변수가 아닌 함수 인자는 FastAPI가 자동으로 Query 파라미터로 인식한다. 검색 조건, 필터링, 페이지네이션 등에 적합하다.

**Q3. 모델 추론 요청에 Request Body를 사용하는 이유는 무엇입니까?**

추론 입력 데이터는 텍스트, 옵션 값, 설정 등 여러 필드로 구성된 **복잡한 구조**이고, 데이터 양이 많을 수 있어 URL 길이 제한에 걸릴 수 있기 때문이다. Request Body는 HTTP 요청 본문에 JSON을 담아 보내므로 크기 제한이 없고 중첩된 구조도 표현 가능하다. 또한 `POST` + Body 조합이 "데이터를 처리해달라"는 의미를 가장 명확하게 표현하는 RESTful 관례이다.

**Q4. FastAPI에서 함수 파라미터가 Path · Query · Body 중 어디서 오는지 어떻게 판별합니까?**

FastAPI는 다음 규칙으로 자동 판별한다:
- 경로 문자열의 `{변수명}`에 포함된 이름 → **Path 파라미터**
- Pydantic `BaseModel`을 상속한 타입으로 선언된 인자 → **Request Body**
- 위 두 경우에 해당하지 않는 일반 타입(`str`, `int` 등) 인자 → **Query 파라미터**

**Q1. FastAPI에서 Swagger UI에 접속하려면 어떤 URL로 이동합니까?**

```
http://localhost:8000/docs
```

FastAPI는 서버 실행 시 이 경로를 자동으로 생성한다. 별도 코드나 라이브러리 설치가 필요 없다.

**Q2. Swagger UI가 코드와 항상 동기화될 수 있는 이유는 무엇입니까?**

Swagger UI는 FastAPI가 `/openapi.json` 엔드포인트에서 자동 생성하는 **OpenAPI 스펙(JSON)** 을 읽어 화면을 렌더링하기 때문이다. 이 스펙은 코드의 타입 힌트, Pydantic 모델, 데코레이터 정보를 런타임에 직접 읽어 만들어진다. 따라서 코드가 바뀌면 다음 요청 시 스펙도 바뀌고, 문서도 자동으로 업데이트된다.

**Q3. Pydantic 모델의 `Field(description=, examples=)`는 Swagger UI의 어디에 반영됩니까?**

- `description`: 해당 필드의 설명 텍스트로 파라미터 또는 Request Body 스키마 항목 옆에 표시된다.
- `examples`: "Try it out" 실행 시 Request body 입력란의 **기본값(예시 JSON)** 으로 미리 채워져 표시된다.

**Q4. Swagger UI와 ReDoc의 핵심 차이는 무엇입니까?**

| 항목 | Swagger UI (`/docs`) | ReDoc (`/redoc`) |
|---|---|---|
| **주 목적** | API 테스트 + 문서 | 문서 열람 |
| **직접 호출** | ✅ "Try it out" 버튼 제공 | ❌ 불가 |
| **레이아웃** | 인터랙티브, 접었다 펴는 구조 | 3-패널 정적 문서 스타일 |
| **실무 용도** | 개발·테스트 단계 | 외부 공개 문서 배포 |

### 섹션 4 체크포인트

**Q1. `text: str`과 `text: str = "기본값"`의 차이는 무엇입니까?**

- `text: str`: **필수 필드**이다. 요청 데이터에 `text`가 없으면 Pydantic이 `ValidationError`를 발생시키고 FastAPI는 422 에러를 반환한다.
- `text: str = "기본값"`: **선택적 필드**이다. 요청에 `text`가 없으면 자동으로 `"기본값"`이 사용된다. 에러가 발생하지 않는다.

**Q2. `Field(..., min_length=1, max_length=5000)`에서 `...`은 무엇을 의미합니까?**

`...`(Ellipsis)은 **필수 필드**임을 선언하는 Python 관례이다. `Field`의 첫 번째 인자는 기본값인데, `...`을 전달하면 "기본값 없음, 반드시 입력해야 함"을 의미한다. `Field(default=..., ...)` 형태와 동일하다.

**Q3. 422 에러 응답에서 `loc` 필드는 어떤 정보를 담고 있습니까?**

에러가 발생한 **위치(위치 경로)** 를 배열 형태로 담는다. 예를 들어 `["body", "text"]`는 "요청 본문(body)의 `text` 필드에서 에러가 발생했음"을 의미한다. Path 파라미터면 `["path", "변수명"]`, Query 파라미터면 `["query", "변수명"]`이 된다.

**Q4. `response_model`을 지정하면 어떤 이점이 있습니까?**

1. **자동 문서화**: Swagger UI에 응답 스키마가 명시적으로 표시되어 API 사용자가 응답 형식을 미리 알 수 있다.
2. **불필요한 필드 자동 제거**: 응답 dict나 ORM 객체에 `response_model`에 정의되지 않은 필드가 있으면 자동으로 걸러내므로, 내부 데이터(비밀번호 해시 등)가 실수로 클라이언트에 노출되는 것을 방지한다.
3. **타입 직렬화 보장**: 응답 데이터가 스키마에 맞게 직렬화·변환되어 일관된 형식이 유지된다.

### 섹션 5 체크포인트

**Q1. 모델을 서버 시작 시 한 번만 로드해야 하는 이유는 무엇입니까?**

모델 로드는 파일 I/O와 가중치 초기화를 포함하는 무거운 작업으로 수 초가 소요된다. 요청이 들어올 때마다 모델을 로드하면 API 응답 시간이 매번 수 초로 늘어나 서비스 품질이 급격히 떨어진다. 서버 시작 시 한 번만 로드하고 메모리에 유지하면 추론 요청에서는 이미 메모리에 올라온 모델을 즉시 사용할 수 있어 응답 속도가 빠르다.

**Q2. `pixel_values`가 784개가 아닌 요청이 들어오면 어떤 일이 발생합니까? 이를 처리하는 코드를 직접 작성했습니까?**

Pydantic 스키마(`schemas.py`)에서 `min_length=784, max_length=784`로 선언했기 때문에, 784개가 아닌 리스트가 들어오면 **Pydantic이 자동으로 422 에러를 반환**한다. 실제 에러 메시지: `List should have at least 784 items after validation, not 100`. 검증 코드를 직접 작성하지 않았다. FastAPI + Pydantic의 선언적 검증이 이를 자동으로 처리한다.

**Q3. `HTTPException(status_code=503)`은 어떤 상황에서 사용했습니까? 왜 500이 아니라 503입니까?**

모델이 정상적으로 로드되지 않은 상태에서 추론 요청이 들어왔을 때 사용했다:

```python
if model is None:
    raise HTTPException(status_code=503, detail="모델이 로드되지 않았습니다.")
```

- **503 Service Unavailable**: 서버 자체는 살아있지만 현재 요청을 처리할 준비가 안 된 상태를 의미한다. 모델 로드 실패는 서버 코드의 버그가 아니라 "지금은 서비스 불가"인 상황이므로 503이 더 적합하다.
- **500 Internal Server Error**: 예상치 못한 코드 오류(버그, 추론 중 런타임 에러 등)에 사용한다.

클라이언트 입장에서 503은 "잠시 후 재시도하면 될 수 있다"는 신호이고, 500은 "서버에 버그가 있다"는 신호이다.

**Q4. Swagger UI에서 `PredictRequest`의 `description`과 `examples`가 어디에 표시됩니까?**

- **`description`**: `POST /predict`의 Request Body 섹션에서 `pixel_values` 필드 항목 옆에 설명 텍스트로 표시된다. 스키마 테이블의 "Description" 열에 해당한다.
- **`examples`**: "Try it out" 버튼을 클릭했을 때 Request body 입력란에 **미리 채워진 예시 JSON**으로 표시된다. 사용자가 수동으로 784개 값을 입력하지 않아도 예시 데이터가 자동으로 들어가 있어 테스트가 편리하다.
